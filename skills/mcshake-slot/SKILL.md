# 麦摇摇 · 麦当劳老虎机

把「今天吃什么」变成一次摇奖：三个滚轮各摇出一件在售餐品，然后回答四件事——

1. **这三件热量多少**（含蛋白质/脂肪/碳水/钠/钙，以及占每日参考值的比例）
2. **多少钱**（走官方 `calculate-price`，带真实促销）
3. **能不能拼 1+1 随心配**（蓝区 + 粉区各一件，套餐价 vs 单点省多少）
4. **真要吃就下单**（通过 MCP 建单，返回付款链接）

## 什么时候用

- 用户说「麦当劳」「麦门」「想吃麦当劳不知道吃啥」「摇一摇」「帮我摇个饭」
- 用户问某家麦当劳的餐品营养、热量、能不能凑单、1+1 怎么搭
- 用户想要一个能直接付款的订单（本技能能建单，但付不了款，见下文）

## 最快上手：一条命令

```bash
node scripts/mcshake.js spin
```

输出就是那四件事。**先跑这一条**，其余命令都是它周边。

## 命令

| 命令 | 作用 |
|---|---|
| `spin [--seed N]` | 摇一局：停位 + 营养 + 计价 + 1+1（主入口） |
| `order preview` | 只算不建单：金额、明细、取餐方式 |
| `order create --take-way <code> --yes` | 真建一笔待支付订单，返回付款链接 |
| `order status <orderId>` / `order cancel <orderId>` | 查状态 / 取消 |
| `symbols` | 列出滚轮里的 11 个符号与单价 |
| `stores [--city 上海] [--keyword 徐家汇]` | 搜门店；不带参数返回收藏门店 |
| `use <序号或编号>` | 记住门店（之后每条命令自动沿用） |
| `serve` | 起常驻服务，用浏览器打开 `http://127.0.0.1:8787` 亲自玩 |
| `status` / `stop` | 看当前记住了哪家店 / 清理残留进程 |

所有命令都支持 `--json`（`status`、`serve`、`stop` 除外），需要自己再加工数据时用。

退出码：`0` 正常，`1` 失败，`2` 需要更多信息（没选门店 / 没摇过 / 建单缺 `--yes`），`3` 找不到项目目录。

## 一次完整交互

```bash
node scripts/mcshake.js spin
# → 板烧鸡腿堡 ¥23.50 391kcal / 麦乐鸡5块 ¥14.00 213kcal / 小杯玉米杯 ¥13.00 53kcal
#   单点 ¥50.50
#   1+1「人气经典随心配」：蓝区·麦乐鸡5块 + 粉区·小杯玉米杯 → ¥13.90
#   板烧不进套餐，本单实付 ¥37.40，省 ¥13.10（7.4 折）

node scripts/mcshake.js order preview
# → 金额 ¥37.40 / 拼成套餐 / 取餐方式 堂食(eat-in) 外带(take-in-store)

node scripts/mcshake.js order create --take-way eat-in --yes
# → orderId + https://m.mcd.cn/mcp/scanToPay?orderId=...
```

把结果讲给用户时，**说人话、别贴终端原文**：讲清摇到了什么、这顿多少卡、省了多少钱、要不要下单。终端排版是给排查问题用的。

## 数据源

| 情况 | 行为 |
|---|---|
| 环境变量有 `MCD_MCP_TOKEN` | 走麦当劳官方 MCP 实时接口，价格、库存、促销都是当下真实的 |
| 没有 Token | 自动进演示模式，用仓库里 `demo/demo-snapshot.json` 的官方数据快照（门店、菜单、营养、286 种三连的真实计价结果），**能玩但非实时** |
| `--demo` | 即使有 Token 也强制用快照 |

演示模式一定要在回答里说明「这是快照数据，非实时」，别让人以为菜单是此刻的。

## 门店

实时模式第一次用会没有门店。技能的处理顺序是：

1. 用上次记住的那家（数据源要对得上：快照里的门店不会被拿到实时模式里用）
2. 用账号的收藏门店——只有一家就自动选，并把店名打出来
3. 多家候选就列出来，让人 `use <序号>` 选

**不要替用户猜店**：门店选错等于把饭点到别的城市去了。`spin` 本身不花钱，但随后的 `order create` 会。

## 三条硬规矩

1. **绝不加 `--yes` 抢跑。** `order create` 会在用户账号里生成真实待支付订单，计入当日下单数。必须先把 `order preview` 的金额和门店讲给用户，得到明确同意，才加 `--yes`。
2. **绝不打印、不落盘 `MCD_MCP_TOKEN`。** 只用环境变量传，`--json` 输出里也不含 Token。
3. **MCP 没有支付能力。** 35 个工具里没有 `pay`/`refund`/小程序跳转。建单后只能拿到 `payH5Url`（H5 收银台），**付款必须由人扫码**。不要说「已帮你付好」，也不要说「已下单到店里」——订单是待支付状态，15 分钟内不付会自动关单。

## 环境准备

- Node 18+（用到全局 `fetch`），项目零依赖，不需要 `npm install`
- 技能默认在仓库里（`<repo>/skills/mcshake-slot/`）；装到用户级技能目录时要让脚本找得到仓库，二选一：
  - `export MCSHAKE_HOME=/path/to/McShake`
  - 或在技能目录写 `config.json`：`{"home":"/path/to/McShake"}`
- 每条命令自带一个临时本地服务（起 → 办事 → 关），**不需要预先起服务**；只有想用浏览器玩才跑 `serve`

## 排错

| 现象 | 原因与处理 |
|---|---|
| `尚未连接 MCP 服务` | 服务刚起来还没握手完，重跑一次；持续出现就是 Token 失效 |
| `今日下单数已经上限` | 官方对单账号每天建单数有限制，等第二天或换账号，**不要重试** |
| `请先输入城市名或地标` | `stores` 需要 `--city`；快照模式只抓了一家店，搜别的城市必然搜不到 |
| `1+1：这家店当前时段没有随心配` | 随心配按餐段上架，早餐时段通常没有。这是正常结果，不是接口坏了 |
| `找不到 McShake 项目目录` | 设 `MCSHAKE_HOME`，或写 `config.json` |

更多接口契约与踩坑（金额单位是「分」、`takeWayCode` 必传、促销自动应用、支付窗口 15 分钟等）见 `references/mcp-contract.md`。
